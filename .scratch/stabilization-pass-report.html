app/user — citizen dashboard

Dashboard cards, one by one

Most of this dashboard turned out to be sample content standing in for data that was already available.

  • Found“Next Up” showed one hardcoded event no matter who was signed in. Wired it to the person's actual bookings and pending requests.
  • Replaced the gamification card with a small live calendar — the bookings you've made, and, separately, anyone else's bookings on things you offer.
  • Turned the flat “For You” grid into a swipeable carousel and made its Music / Art / Food filters actually filter, instead of sitting there unclickable.
  • FoundRemoved the “Venues Available” list, which duplicated another section, and a placeholder link that would 404 on click.
  • “Saved Vibes” had no upper bound and would grow forever as favorites piled up — added paging, four at a time.
  • Removed two header buttons ("Messages", "Settings") that didn't lead anywhere.
creator-dashboard/calendar

The month view, redesigned

Rebuilt from a plain grid into a two-pane month + day-detail layout, then spent most of the polish on things that only show up once you actually look closely.

  • Month picker and year controls now sit next to the calendar they control, not off in a separate header.
  • Selecting a day and “today” no longer fight for the same color — each now has its own, and the color for a selected day was toned down from neon to something easier to look at.
  • Booking types (events, venues, gear, services) are labeled with small icons instead of a color key, so nothing depends on telling four similar hues apart.
  • FoundDay cells changed size depending on how many weeks the month had. Every month now renders the same fixed grid.
  • Swapped translucent overlay colors for solid ones throughout — the washed-out, slightly-blurry look was coming from stacked transparency, not an actual rendering bug.
wishlists — saved items page

A page that had never been connected

What looked like one bug — hardcoded cards — turned out to be three, stacked on top of each other.

  • FoundBoth the desktop and mobile saved-items pages were entirely mock data; neither had ever called the real save/favorite feature.
  • FoundUnderneath that: the favorites API never actually looked up the venue or event a favorite pointed to, so even the correct page would have shown blank titles.
  • FoundAnd under that: a field-naming mismatch meant the app could never correctly tell whether something was already saved, anywhere it appeared.
  • Fixed all three, then rebuilt both pages against the real data, including a proper header and back button on the desktop page, which had neither.
auth — sign in / sign out

Three ways to log out, only one of them complete

  • FoundThe screen shown to a signed-out visitor was the sign-up form, not sign-in — for someone who just logged out, that's the wrong default.
  • FoundOf three separate “log out” buttons in the app, one skipped clearing the session cookie entirely, and one on mobile did nothing at all.
  • Consolidated all three into one, and every sign-out now returns to the sign-in screen (except right after deleting an account, where there's nothing to sign back in to).
  • FoundThe sign-up form would silently fill in a previous visitor's saved username and password — it was missing the field markers that tell a browser “this is a new account, not a login.”
build & CI

Why a build sat unfinished for half an hour

  • FoundThe production build had switched to a newer, faster bundler by default — one that skipped a required manual step for two specific libraries. Without it, the build tried to fully process a large mapping library and a satellite-tracking library that neither is meant to be processed that way, and hung.
  • Pointed production builds back to the older, already-working bundler; a full build now finishes in well under a minute.
  • Removed the satellite-tracking feature (an ISS marker on the map) and its library entirely, at request, rather than keeping the workaround.
  • FoundA leftover set of pages from before a URL restructuring was still shipping — every one of them just redirects elsewhere now, but they were failing the build's type checks. Deleted the whole leftover set.
  • FoundThe CI cache key was accidentally including the entire installed-dependencies folder, which made it change on nearly every run and defeated the point of caching. Narrowed it to the actual source files.
Everything above was verified directly — either by re-running the affected page, or, for the build issues, by running a full production build end to end and confirming it completes cleanly.
